# Context

現行スキルは、Purpose、Spec、Evidenceを参照して独立レビューを行い、重大度・必須マーカー・人間裁定を管理する。今回の変更では、その既存の証拠重視と独立性を維持しつつ、家庭内LANなどの限定環境で一般的なセキュリティ推奨が目的外のブロッカーへ拡張されることを防ぐ。

## Goals / Non-Goals

**Goals:**

- レビュー開始時に目的とリスクプロファイルを固定する。
- Findingの目的適合性、重大度、技術判定、リスク裁定を別概念として記録する。
- `proportional-home`を選択可能にし、リソース制約に適合した証拠要求を定義する。
- 実機未接続などの未検証状態を不合格と区別する。
- リスク受容の監査可能性を高める。

**Non-Goals:**

- セキュリティ要求を廃止すること。
- CriticalまたはHighのFindingを自動的に受容可能にすること。
- 既存QAケースの履歴や判定を遡及的に書き換えること。
- QAスキル実行時の外部依存関係を追加すること。

## Decisions

### Decision 1: スキル本体と参照資料の責務を分ける

判定順序、必須状態、出力項目は`SKILL.md`に置く。プロファイルの適用条件と証拠要求の差は`references/risk-profiles.md`、Findingの分類・重大度・状態は`references/finding-taxonomy.md`、一般原則は`references/qa-principles.md`に置く。これにより、主要手順を短く保ちつつ、詳細の更新を局所化する。

### Decision 2: 技術判定とリスク裁定を別フィールドにする

技術判定は、実装と証拠が要求を満たすかを表す。リスク裁定は、所有者が残余リスクを受け入れたかを表す。リスク受容後も技術判定は修正済みへ変換しない。これにより、後日の再評価で未修正の技術負債を見失わない。

### Decision 3: `proportional-home`は重大度を下げる仕組みではなく、要求の出所を検査する仕組みにする

家庭用プロファイルでは、目的に直接影響するデータ欠損・重複・意味変質を優先する。一方、仕様にない一般的な防御策は運用衛生または判断待ちとして提示する。秘密情報のリポジトリ保存や無制限の破壊など、環境にかかわらず重大な問題は従来どおり指摘する。

### Decision 4: 既存の状態語との互換性を維持する

既存の`fixed-and-verified`、`partially-fixed`、`risk-accepted`、`adjudication-required`は保持する。新たに技術判定と裁定を分離して記録できるようにし、既存ケースの履歴ファイルを一括変換しない。

## Risks / Trade-offs

- [過少評価のリスク] 比例性を理由に重要なセキュリティ問題を見逃す → 仕様・目的・脅威モデルとの関係を確認し、リポジトリへの実秘密保存や目的直結のデータ破壊はプロファイルに関係なく指摘する。
- [記録項目増加] Findingの記入負担が増える → 必須項目を分類、技術判定、裁定、受容根拠に限定し、テンプレート例を提供する。
- [既存記録との不整合] 旧ケースに新フィールドがない → 履歴は保持し、次回の再レビューまたは更新時から新形式を適用する。
- [環境前提の誤記録] 家庭内LANの前提が将来変わる → 外部公開、用途変更、インシデント、機器更新を見直しトリガーとしてリスク受容記録に残す。

## Migration Plan

1. スキル本体と参照資料を更新する。
2. スキル検証テストと代表評価ケースを実行する。
3. 既存QAケースは履歴を保持したまま、新しい裁定記録が必要な場合のみ追記する。
4. 問題があれば変更前のスキルファイルへ戻し、評価結果を記録する。
