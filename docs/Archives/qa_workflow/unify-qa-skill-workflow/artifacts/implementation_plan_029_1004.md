## 目的

QA依頼のたびに計画書と個別承認を挟まず、定義済みの範囲でローカルQAとクラウドQAを速やかに実行できるよう、ルートの`AGENTS.md`に限定的な事前委任ルールを追加する。独立QAの判定、製品修正、Findingの裁定、マージ、配備に対する人の判断境界は維持する。

## 変更対象

- `AGENTS.md`のみ。
- 既存のQA関連節と段階的承認ルールの近くに「QAループの定型実行（限定委任）」節を追加する。
- 既存の作業ツリー変更、削除、未追跡成果物には触れない。

## 追加するルール案

QA Skillを明示してQA実施を依頼した場合、その依頼を、Skillに定義されたローカルQA成果物の作成と、クラウドQAの固定済み依頼パケット・QA専用コミット・新規topic branchへの通常pushに対する実行指示として扱う。これらの定型QA手順には個別のimplementation plan作成・承認を求めない。ただし、対象差分と全受入基準が固定され、許可対象パス内であり、テスト・機密情報・個人ローカルパス・remote ancestryの各事前検査が通る場合に限る。

Reviewerにはbaselineとreviewed SHAで固定した差分、全受入基準、自己完結したQA指示を渡す。実施者AIの説明はレビュー結論の根拠とせず、Reviewer自身が根拠を記録する。実施AIはQA結果やFindingを変更・削除・選別しない。

対象範囲の追加・曖昧さ、受入基準の欠落、機密情報または個人パスの検出、テスト失敗、既存branchとの衝突、remote履歴の不整合、または明示許可範囲外の変更がある場合は、QA公開を停止して人に判断を求める。製品コード・仕様の修正、Finding disposition、Owner裁定、merge、production deploymentは引き続き別途明示承認を必要とする。通常QAの依頼はこの限定委任内で処理し、QA指示を受けたことだけを製品変更の承認とはみなさない。

## 実施と検証

本計画の承認後、作業開始時に`AGENTS.md`の差分を再確認し、上記節だけを追加する。変更後は差分が`AGENTS.md`の該当追加に限定されていること、日本語・用語・承認境界が明確であること、QA公開と製品変更の権限が混同されないことを確認する。既存のユーザー変更は保持し、commit・pushは行わない。
